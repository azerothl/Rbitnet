Rbitnet

Pure-Rust GGUF inference — OpenAI-compatible API, native BitNet path, no external engine at runtime.

Install Documentation

A warren for bits

Rbitnet mmaps the GGUF, dequantizes weights, runs the transformer, and serves tokens — self-contained in Rust, built as the satellite inference backend for Akasha (BitNetProvider on port 8080).

What ships today

  • bitnet-core Llama / Qwen3 / BitNet b1.58 GGUF, CPU quantized kernels, paged & quantized KV hooks.
  • rbitnet-server OpenAI /v1 HTTP, SSE streaming, health / ready / Prometheus metrics, hot reload.
  • rbitnet CLI Curated catalog, Hub download, quickstart, TUI chat, BitNet recipes, optional train helpers.

Status

Production-ready is not claimed yet — HTTP surface, CI, and core GGUF paths are solid; fused GPU serving and full multi-seq batching remain open.

Roadmap focus

Native-first CPU remains the default. Research priorities track serving gaps vs vLLM-class stacks without chasing every industry feature.

  • Near term Metrics UX (TTFT, prefix_hit, draft_accept), provenance/SHA, structured output, bench gates vs llama.cpp.
  • Medium Fused multi-seq continuous batching, SlimAttention-style CPU tiling, K/V asymmetry after KV Q8, tune profiles.
  • Strategic GPU_NATIVE device KV + fused attention, BitNet packed GPU kernels, optional Metal — after frozen CPU benches.

Install

One checkout, one binary. Python only if you convert checkpoints to GGUF upstream.

curl -fsSL https://raw.githubusercontent.com/azerothl/Rbitnet/main/scripts/install.sh | sh
rbitnet models install tinyllama-1.1b-chat-q4-k-m --dir ./models
rbitnet up tinyllama-1.1b-chat-q4-k-m --dir ./models
rbitnet serve

Windows: .\scripts\install.ps1 · Get started · FR quickstart

In the Akasha stack

akasha-os keeps llama.cpp inside the Preview TCB. The Akasha daemon consumes Rbitnet over HTTP on port 8080 — separate roles, frozen /v1 + /metrics contract.
