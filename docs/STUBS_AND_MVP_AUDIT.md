La disponibilité d'un backend de bas niveau reste une capacité, pas la preuve que toutes les opérations du modèle s'exécutent sur GPU. Les métadonnées de placement, compteurs réels et scripts matériels précisent les chemins partiels. Une erreur native est remontée ; aucun état CPU divergent n'est substitué au milieu d'une séquence.

Les modes intentionnels restent explicites : STUB fournit une réponse synthétique marquée ; TOY un petit LM F32 sans GGUF. Leur backend effectif est CPU. LoadFailed et unload idle remplacent l'engine sans prouver la validité d'un modèle ; readiness et les six routes unary/SSE bloquent les erreurs de chargement. Le serveur relâche sa référence de démarrage afin que le déchargement libère réellement le modèle ; une requête encore active conserve sa référence jusqu'à sa fin. Le SSE natif Llama/Qwen3.5/GPT-OSS/GLM suit la génération, tandis que le fallback ModelExecutor attend la complétion puis un delta.

Les métriques utilisent le working set Linux /proc ou Windows PSAPI. La VRAM totale par processus est encore **non mesurée** : le placeholder constant process_vram_bytes=0 est supprimé, remplacé par une disponibilité à zéro. Les nouvelles jauges CUDA comptent le sous-ensemble possédé par Rbitnet, par catégorie, sans doubler les vues ou les leases ; le scratch conservé après unload reste compté. Elles n'incluent pas les allocations internes du pilote et des bibliothèques. [Migration du contrat](AKASHA_METRICS.md), [contrat du budget commun](PERFORMANCE_CACHE_STACK.md).

#24 reste ouvert pendant les conversions requises, avec #22 et #83–#97 ; il ne se résume plus au seul matériel #22. Les tests CPU avec early return GPU, les probes et les tickets historiques fermés ne suffisent pas à promouvoir un chemin matériel. Chaque livraison publie code, contrôles actifs, mesures et replis.
